# 判断层文字不写死机器数 · 只写 token · 机器数由渲染层填（v1）

> 立于 2026-08-09（轮333·董事长令）。与 CLAUDE.md §5.5「数据层文案不许夹带 HTML 标签」同一族规矩：
> **各层只管自己那摊，别跨层塞东西。**

## 一、规矩（一句话）

**Opus5 拥有的判断层文件（`data/forward/`、`data/analysis/`、`data/pipeline/judgment_slots_*` 等）里，
不许写死机器算出来的数（板块强度、有效样本数等）；只写占位符 token，机器数由渲染层按当日实算值填。**

## 二、为什么（轮333 踩过的坑）

- 轮332 曾用【渲染层正则去改判断文字里的数字】(`_sync_sector_readings`)。三条正则写死了 Opus5 当时的中文措辞。
- 三个风险：
  1. **措辞一改，正则静默失配** → 数字重新变陈旧，无报错无告警，没人知道。
  2. **渲染层改判断层文字＝越界** —— 判断是 Opus5 的，渲染不该动它。
  3. 这正是 CLAUDE.md §5.4 禁的「靠自由文本关键词」——只不过这次是改写不是判定，更危险。
- 根治＝**占位符化**：判断层写 token，渲染层填数。两层各管各的。

## 三、Token 语法

```
{SS.<格号>.<字段>}
```
- `SS` = sector_strength（板块强度）。
- `<格号>` = 板块格号（如 18 国防军工、19 网络安全）。
- `<字段>` 限六个：
  - `r5` / `r20` / `r60` = 5日 / 20日 / 60日 **相对强度**（渲染填带正负号两位小数，如 `+33.43`）
  - `n5` / `n20` / `n60` = 5日 / 20日 / 60日 **有效样本数**（渲染填整数）

**示例**（判断层这样写）：
```
拆格后纯核心读数：网络安全 5只 60日 {SS.19.r60} ／ 20日 {SS.19.r20}
```
渲染出来（管道版/五册）：
```
拆格后纯核心读数：网络安全 5只 60日 +33.43 ／ 20日 +6.74
```

## 四、机器侧落地（已实现·轮333）

- **渲染填 token**：`scripts/product_blocks.py::fill_sector_tokens(root, dc, html)`。
- **★查不到值→渲染 FAIL·不静默**（甲3）：token 的格号缺 / 字段非法 / sector_strength 文件读不到 → `raise ValueError` → 不出品。
  - 例外：值本身 = None（如 60日样本不足）→ 填「N/A」（合法·非陈旧）。
- **值=None 合法**：样本不足该周期本就无数，填 N/A 是对的，不算 FAIL。
- **L56 告警闸**（甲4·`product_lint.py::_l56_bare_sector_numbers`）：判断层文件里出现【看起来像板块强度的裸数字】而非 token → 写 `data/logs/l56_warnings_{date}.json` 告警。
  - ★**先告警不阻断**（观察期一周·看误报率再定是否升 FAIL）。

## 五、Opus5 侧要做的（迁移）

- 新写判断文字，板块强度/样本数一律用 token，不写死数字。
- 存量文件（forward 里 AI存储/AI软件应用等其它板块的裸数字）按 L56 告警逐步 token 化。
- `forward_20260808.json` 的网络安全三处已迁移为 token（轮333）。
