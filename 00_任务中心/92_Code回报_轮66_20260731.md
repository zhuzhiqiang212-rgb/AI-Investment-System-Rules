## AE3 · 今早新闻 FAIL 的真因（已修）

- **AE3-1 真因**：**不是超时、不是源不可达、不是限流、不是脚本卡死**，是**依赖顺序缺陷**。⓪ `daily_scan.py` 的新闻硬闸读的是 `data/evidence_chain/daily_{date}.json`，而这个文件由 ②a `evidence_autobuild`（→`macro_news_intake` 才真抓新闻）**更晚两步才建**。新日期首跑时它不存在 → 新闻计数 0 → 硬闸拦停 **rc=7**。日志里的"超时(124)"是 `critical_step_failed` 的**通用标签文案**（它对任何非零 rc 都印"rc=X(超时=124/非零)"），真实 rc 是 7、真抓新闻的 `macro_news_intake` 那一刻**还没轮到跑**。已证：`evidence_chain/` 里当时只有 `daily_20260730.json`、无 `daily_20260731.json`。
- **修法（AE3-2：不降级、不跳过，只挪到新闻真被抓之后再判）**：
  1. `daily_scan.py` ⓪ 的硬闸**移除新闻项**（只保留价/涨跌榜/Drive新增——都是本步真能产出的），新闻改为**只记录不硬拦**。
  2. 新闻硬闸**移到 evidence_autobuild 抓完之后**：`daily_auto_produce.verify_output` 对 `evidence_autobuild.py` 增 `news_present` 强校验（`_count_news` 数 macro_news+links·口径与 daily_scan 一致）——抓不到任何新闻 → ②a 关键步失败 → **整轮停**。闸没弱化，只是从"新闻还没抓就判"改成"新闻抓完再判"。
- **AE3-3**：新闻源真连不上 → evidence 无新闻 → ②a 整轮停、如实记"新闻源连不上·未生产"，不拿旧闻顶充。
- **空跑实测**：dry-run 中 ⓪ daily_scan rc=0（新闻已移出硬闸）、②a evidence rc=0（有新闻·news_present 过）。
